# fastly_ngwaf_workspace_signal (Resource)

Manages a Fastly Next-Gen WAF custom signal scoped to a single workspace.

Workspace signals are versionless and belong to an NGWAF workspace, not to a
Fastly service version. The generated `reference_id` can be used by other NGWAF
configuration, such as workspace rules.

## Example Usage

```terraform
resource "fastly_ngwaf_workspace" "example" {
  name        = "Example Workspace"
  description = "Managed by Terraform"
  mode        = "block"

  attack_signal_thresholds {}
}

resource "fastly_ngwaf_workspace_signal" "example" {
  workspace_id = fastly_ngwaf_workspace.example.id
  name         = "Login Attempt"
  description  = "Tracks login attempts for workspace rules"
}
```

## Schema

### Required

- `name` (String) The name of the signal. Must be between 3 and 128 characters and contain only letters, numbers, spaces, and hyphens. The name is immutable after creation.
- `workspace_id` (String) The ID of the workspace that owns the signal.

### Optional

- `description` (String) The description of the signal. Maximum length is 140 characters.

### Read-Only

- `id` (String) The workspace signal identifier generated by Fastly.
- `reference_id` (String) The generated reference ID of the signal, for example `site.foo-signal`.

## Import

Workspace signals are imported using a combination of the workspace ID and the
signal ID, separated by a `/`:

```shell
terraform import fastly_ngwaf_workspace_signal.example WORKSPACE_ID/SIGNAL_ID
```
