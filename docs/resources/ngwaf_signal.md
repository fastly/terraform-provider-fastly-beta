# fastly_ngwaf_signal (Resource)

Manages a Fastly Next-Gen WAF custom signal defined at account scope.

Account-scoped NGWAF resources omit `account` from their Terraform names. The
workspace-scoped custom-signal resource is `fastly_ngwaf_workspace_signal`;
this resource is the account-scoped counterpart.

`applies_to` accepts either one or more workspace IDs or the single value `*`
to apply the signal to every workspace in the account. The generated
`reference_id` can be referenced by other NGWAF configuration.

The signal `name` is immutable. Updating `description` is performed in place.

## Example Usage

```terraform
resource "fastly_ngwaf_signal" "login_attempt" {
  applies_to  = ["*"]
  name        = "Login Attempt"
  description = "Tracks login attempts across the account"
}
```

## Schema

### Required

- `applies_to` (Set of String) The workspaces this signal applies to: a set of workspace IDs, or the single entry `*` to apply the signal to every workspace in the account. The two forms are alternatives - the wildcard cannot be combined with named workspace IDs.
- `name` (String) The name of the signal. Must be between 3 and 128 characters and contain only letters, numbers, spaces, and hyphens. The name is immutable after creation.

### Optional

- `description` (String) The description of the signal. Maximum length is 140 characters.

### Read-Only

- `id` (String) The signal identifier generated by Fastly.
- `reference_id` (String) The generated reference ID of the signal, for example `site.foo-signal`.

## Import

Account-scoped custom signals are imported using the signal ID alone.

```shell
terraform import fastly_ngwaf_signal.login_attempt SIGNAL_ID
```
